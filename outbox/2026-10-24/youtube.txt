TITLE
The object should remember

DESCRIPTION
The gestures started landing; the harder problem became continuity — a selected face, a held intention, and a multi-step edit that survives the next sentence.

In the headset:
- The whiteboard retest — video pickup, play-while-held, pause-on-release and stay-put all pass. The five media items move flush onto the whiteboard. Hover-to-arm and the two-curl summon both work, but the curl does not trigger consistently, and hover-to-arm gets unreliable when an item is locked to the wall grid.
- The cube gets a look — the 50mm cube preview is transparent with solid edges; accepting it keeps that appearance and all three grab modes work: contact, hover and distance. The preview material becomes the default for accepted models after 2,382 tests and 84 native model checks pass. A duplicate request still comes back as ambiguous.
- The missing memory — the cube knows the selected Z-face and the request for 50mm more, but the next message arrives without that face selection and the edit is rejected. Supplying the face ID is not enough: the validator also demands that the face was selected in the current message or named literally in it. The fix is to preserve the chosen target between turns.
- The broader blocker — one broad conflict flag can reject a model command whenever pose, hover or selection changes during speech, even when the change is unrelated. There is no true “duplicate this live object” operation yet. Scrolling in dialogue history and the queue, and Combine with previous, may be blocked by the same pinch-detection problem.
