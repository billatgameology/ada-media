Project development timeline · 30 October 2026

From a room that works to a product that ships.

The next stretch is a sequence of gates, not a calendar. Basic operations come first. The content workflow and the MVP are earned on top of that foundation. After the MVP, the roadmap deliberately splits.

We are herePhase 1

Basic operations

Make the room dependable enough to build on.

  • Voice, panels, media and gestures work without developer rescue.
  • Layouts, notes and positions survive save, reload and restore.
  • Failures are explicit and recoverable — no silent success.

Current focus: panel save/restore · voice overlap · whiteboard placement

Phase 2

Content creation workflow

Complete one real creative job inside the room.

  • Collect references, arrange them, and create the artifact in place.
  • The full loop survives interruption, save and reload.
  • The result is shareable without another tool doing the real work.

Phase 3

MVP

A first-time user can finish the core job in one session.

  • One workflow runs end-to-end at acceptable speed.
  • Setup, onboarding and recovery no longer need the builder.
  • Real users can try it and show us where it breaks.

After MVP · Track A

Refine content creation

Make the proven workflow deeper, faster and worth returning to.

  • Fix the friction real usage exposes.
  • Add templates, deeper editing and durable projects.

After MVP · Track B

Use case #2 workflow

Test whether the same core can carry a second job.

  • Name the use case and its success criteria.
  • Reuse the primitives; build a separate end-to-end workflow.

Open decision: use case to be named.

Sequencing

Gates, not dates

A phase ends when its exit criteria are true, not when a calendar page turns. The order is stable; the dates are earned.

Architecture

One core, many workflows

The split happens above the platform. Voice, panels, media, memory and save/restore stay shared.

Evidence

Real sessions, real reloads

Every gate needs a real headset session, a real reload and a result that survives both. A demo is not the gate.
